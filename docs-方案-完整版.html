Technical Proposal

15 灯跑马灯喝酒游戏 · 控制方案

硬件由甲方按清单自制，软件（固件 + 配置端）由乙方提供。本方案解决一个核心问题：如何在"看起来是随机停下"的前提下，精确控制停下来的亮灯数量和排除指定灯。

灯数 15 路 亮灯数 2 或 3（可切换） 控制 单按钮 + 禁用开关 + 手机网页 推荐硬件 ESP32 + WS2812B

二、核心原理：先定结果，再演过程

这一节是整个方案的技术关键，也是必须提前讲清楚的一点。

纯硬件的跑马灯做不到您要的效果

跑马灯物理上停下来，只能停在一盏灯上。您要的是停下来恰好亮 2 盏或 3 盏，还要排除指定灯——这不可能靠「让灯转到那停」实现，必须由软件来演。

做法分三步：

  1. 拍停的瞬间，软件先在内部把结果定好。从「当前启用的灯」里随机抽取 N 盏（N = 2 或 3），抽完就固定不变。这一步客人看不见。
  2. 用 0.6~0.9 秒把这盏结果「演」出来。跑马灯从高速逐渐减速，跳跃间隔越拉越长，最后几次跳跃精准落在那几盏目标灯上，其余灯全部熄灭。视觉上就是转盘慢慢停下来的效果。
  3. 结果呈现。目标灯高亮并闪两下，配合提示音，保持十余秒让全场看清谁喝。
为什么客人不会看出破绽

因为跑马灯阶段本来就是无规则乱闪，没有刻度、没有指针、没有可对照的固定位置。客人无法从「停在哪」反推「应该亮几盏」——两者的因果关系在观感上根本不存在。这跟老虎机、抽奖转盘是同一类做法，也是行业内通行方案。

另外一个附带好处：结果由芯片的硬件随机数产生，跟跑马灯走到哪儿完全无关。如果哪天客人质疑公平性，这反而是最容易解释的一种——比"手动停"更公平。

五、接线要点

这六条是这个方案里最容易翻车的地方，按清单做能省掉一晚上的排查：

#要点不做会怎样
1ESP32 输出 3.3V 逻辑，WS2812B 要求数据线高电平 ≥3.5V，必须经 74AHCT125 升到 5V颜色乱闪、后半段灯完全不受控、偶尔全灭
2数据线串 330~470Ω 电阻，尽量靠近第一颗灯信号振铃，长线时出现随机闪白
3电源输出端并 1000µF 电解电容上电瞬间电流冲击，第一颗灯容易烧
4灯的 VCC / GND 从电源直接拉，不要从主板的 5V 引脚取电电流超载，烧主板稳压芯片
5注意灯珠方向，DIN 进 DOUT 出，接反了后面全不亮只有前几颗亮，后面一片黑
6按钮线远离数据线，按钮两端并 100nF 电容消抖拍一下触发两次，游戏变成连跳

15 颗灯满载功耗约 5V × 0.9A ≈ 4.5W，10A 电源余量充足，后续加到 30 颗也不用换。

六、软件功能与可调参数

固件跑在 ESP32 上，内置一个手机配置页——不用装任何 App，手机连上设备发出的 WiFi，浏览器打开就是设置界面。

运行状态

待机（呼吸微光，等拍）→ 乱闪（一拍启动）→ 减速收束（二拍锁定）→ 亮灯展示（保持十余秒）→ 自动回到待机。

可调参数

参数可设范围默认值怎么改
亮灯数量2 盏 / 3 盏2手机网页，或遥控器 A / B 键
禁用灯1~15 号任意组合全启用拨动开关（自动同步），或手机网页
乱闪最高速度20~80 毫秒 / 步35手机网页
收束时长0.4~1.5 秒0.7手机网页
结果保持时间5~60 秒15手机网页
灯光颜色任意色 / 呼吸 / 彩虹暖白手机网页
提示音开 / 关 / 音量开手机网页

所有参数存在芯片的 Flash 里，断电不丢。店里每天开关机不用重新设置。

防误操作设计

  • 结果展示期间按钮暂时失效，防止客人连拍把一局跳过去（时长可配）。
  • 上电默认全灭待机，绝不会一通电就亮灯吓到人。
  • 程序卡死时看门狗会 8 秒内自动复位回待机，不会停在半亮状态。
  • 禁用开关状态每次启动都读，断电也保持。
